# Windows 사용 방법

## 1. 어떤 방식으로 사용할까요?

- **웹만 사용:** [스터디 플래너 웹](https://vikira12.github.io/study_plan/)을 연다. 프로그램 설치 없이 사용할 수 있지만, 이 주소의 개인 일정은 배경화면에 자동 반영되지 않는다.
- **웹과 배경화면 함께 사용:** Windows 설치판이나 로컬 서버를 사용한다. 개인 일정은 같은 Windows 계정의 PC 안에 저장되고, 웹과 배경화면이 같은 자료를 읽는다. 학교는 대덕소프트웨어마이스터고등학교로 고정되어 있다.

**설치 ZIP은 아직 GitHub Release에 공개하지 않았다.** 최신 소스로 만든 ZIP을 제작자에게 전달받아 설치하거나, 아래의 소스 실행 방법을 사용한다. 이전에 만든 ZIP은 최신 저장 보호 수정이 빠져 있으므로 제작자가 다시 생성·검증해야 한다. ZIP 제작 방법은 [Windows 배포 안내](windows-distribution.md)에 있다.

## 2. 설치 ZIP을 전달받았다면

1. 일반 Intel/AMD 64비트 Windows PC는 파일명에 `Windows-x64`가 있는 ZIP을 받는다. ARM PC는 제작자에게 호환 여부를 확인한다.
2. ZIP을 우클릭하고 **모두 압축 풀기**를 선택한다. ZIP 내부에서 바로 실행하지 않는다.
3. 풀린 `StudyPlanner` 폴더에서 **설치.cmd**를 실행한다. Node.js를 따로 설치할 필요는 없다.
4. 설치가 끝나면 안내 화면이 열린다. **내 달력 열기**를 누르거나 바탕화면의 **Study Planner** 바로가기를 실행한다.
5. 이후 웹 사용 주소는 **http://127.0.0.1:3000/** 이다. 서버는 Windows 로그인 시 자동 실행되도록 등록된다.

기존 개발 서버가 켜져 있으면 3000 포트 충돌로 설치가 중단될 수 있다. 먼저 기존 웹의 일정을 내보내 백업하고, 그 서버를 시작한 터미널에서 `Ctrl+C`로 종료한다. 자동 시작된 서버라면 해당 앱의 실행 경로를 확인한 뒤 종료한다. 다른 프로그램의 `node.exe`까지 일괄 종료하지 않는다. Windows 보안 경고나 조직 정책으로 차단되면 출처를 확인하고 관리자에게 문의하며, 백신을 끄지 않는다.

## 3. ZIP 없이 소스로 실행하려면

이 방식은 Git과 Node.js가 설치된 PC에서 사용한다. 터미널에서 원하는 작업 폴더로 이동한 뒤 실행한다.

```powershell
git clone https://github.com/vikira12/study_plan.git
cd study_plan
node server.js
```

브라우저에서 **http://127.0.0.1:3000/** 을 연다. 서버가 실행된 터미널을 닫으면 웹과 배경화면의 로컬 연결도 끊긴다. 같은 PC에 이미 저장소가 있다면 새로 복제할 필요 없이 최신 소스를 확인하고 해당 폴더에서 실행한다. `index.html`을 직접 여는 방식은 전체 기능용이 아니다.

로그인 때 서버를 자동 실행하려면 저장소 폴더에서 한 번 등록한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows-startup.ps1
```

등록 명령은 서버를 즉시 시작하지 않는다. 현재 세션에서는 `node server.js`로 실행하고, 다음 로그인부터 자동 시작되는지 확인한다. 실행 정책 옵션은 이 명령에만 적용하며 시스템 정책이나 백신을 변경하지 않는다. 프로젝트 폴더나 Node.js 위치를 옮기면 새 경로에서 다시 등록한다.

## 4. 배경화면에 달력 표시하기

1. 먼저 로컬 웹이 열리는지 확인한다.
2. [Lively Wallpaper 공식 홈페이지](https://www.livelywallpaper.net/)에서 Lively를 설치하고 실행한다. Lively는 설치 ZIP에 포함하지 않는다.
3. Lively의 **배경화면 추가 → URL**에 **http://127.0.0.1:3000/wallpaper.html** 을 입력하고 적용한다.
4. Lively 설정에서 **Windows 시작 시 실행**을 켠다. 서버 자동 시작과 Lively 자동 시작은 별개이다.
5. 달력 상단을 끌어 이동하고, 테두리·모서리를 끌어 크기를 바꾼다. 원하는 배치가 되면 **배치 잠금**을 누른다. 원래 위치로 돌아가려면 **배치 초기화**를 사용한다.

배경화면에는 개인 일정, 학교 일정, 공휴일과 오른쪽의 오늘 급식이 보인다. 급식 날짜는 한국 시간 기준이며 조식·중식·석식이 없는 경우 따로 안내한다. 배경화면은 읽기 전용이므로 일정 추가·수정은 웹에서 한다. 개인 일정은 약 15초마다 반영된다. 마우스로 이동·크기 조절이 안 되면 Lively의 배경화면 상호작용 설정을 확인한다.

## 5. 일정 관리하기

1. **일정 입력**에서 제목, 시작·마감 날짜, 유형과 알림 기준을 선택하고 **일정 추가**를 누른다. 날짜 빠른 선택 버튼도 사용할 수 있다. 빈 제목과 공백만 있는 제목은 저장하지 않는다.
2. **달력**에서 날짜별 일정을 확인한다. 개인 일정을 드래그해 이동하고 일정의 양 끝에서 기간을 조정한다. 날짜 단위이며 시간 단위는 사용하지 않는다.
3. **내 일정**의 완료 체크박스를 누른다. 다시 누르면 완료가 해제된다. 달력에서는 개인 일정을 우클릭해 완료 여부를 바꿀 수 있다.
4. 내용을 바꾸려면 **수정**, 없애려면 해당 일정의 **삭제**를 누른다. 학교 일정은 공개 자료이므로 개인 일정처럼 수정하지 않는다.
5. 검색과 상태 필터로 일정을 찾고, 헤더의 모드 전환 버튼으로 다크 모드를 사용할 수 있다. 달력 크기 선택으로 한 화면에 맞춘다.
6. **학교 급식표**에서 날짜를 골라 메뉴를 확인한다. 중요한 학교 일정과 식단은 학교 원본도 대조한다.

마감 임박 안내는 앱 안에서 확인한다. 브라우저 알림은 사용자가 버튼을 눌러 권한을 허용해야 하며, 앱을 닫은 동안 보내는 알림은 지원하지 않는다.

## 6. 기존 일정 옮기기와 백업

1. 일정이 남아 있는 기존 주소를 열고 **내 일정 → 개인 일정 내보내기**를 누른다.
2. 내려받은 JSON 파일을 별도로 보관한다.
3. **http://127.0.0.1:3000/** 의 **내 일정 → 개인 일정 가져오기**에서 그 파일을 선택한다.
4. 일정 제목·날짜·완료 상태를 확인하고 새로고침해 유지되는지 확인한다. 같은 ID의 일정은 중복 추가하지 않으며 기존 값을 유지한다.

이후 **로컬 웹에서 수정해야 배경화면에도 반영된다.** GitHub Pages에서 수정한 값은 로컬 웹으로 자동 이동하지 않는다. PC와 Windows 계정 사이 자동 동기화도 없다. 같은 Windows 계정을 함께 쓰면 같은 개인 일정 파일을 사용하므로, 서로 다른 일정이 필요하면 Windows 계정을 분리한다.

개인 일정은 `%LOCALAPPDATA%\StudyPlanner\tasks.json`, 달력 배치는 같은 폴더의 `wallpaper-layout.json`에 저장한다. 일정 변경 전 최근 10개 백업은 `backups` 폴더에 보관하지만, 주기적으로 **내보내기**도 사용한다. 개인 일정은 GitHub와 설치 ZIP에 포함하지 않는다.

## 7. 잘 안 될 때

| 증상 | 확인할 일 |
| --- | --- |
| 로컬 주소가 열리지 않는다 | 설치판은 바탕화면 바로가기로 다시 실행한다. 소스 방식은 `node server.js`가 실행 중인지 확인한다. |
| 3000 포트 사용 안내가 나온다 | 기존 서버나 다른 앱을 확인한다. 설치기는 다른 앱을 자동 종료하지 않는다. |
| 서버 최신 버전 안내가 나온다 | 현재 일정을 내보내 백업하고 이전 서버를 종료한 뒤 최신 소스나 설치판으로 다시 실행한다. |
| 로그인 직후 배경화면만 오류가 난다 | 로컬 웹이 열린 뒤 Lively에서 배경화면을 다시 불러온다. |
| 웹에서 고친 일정이 배경화면에 안 보인다 | 편집 주소가 Pages가 아닌 `127.0.0.1:3000`인지 확인하고 약 15초 기다린다. |
| 학교 일정·급식을 못 불러온다 | 인터넷 연결과 새로고침을 확인한다. 스냅샷 표시라면 최신 자료가 아닐 수 있다. |
| 저장 충돌·동기화 실패 안내가 나온다 | 일정을 내보내 백업하고 다른 편집 창을 닫은 뒤 새로고침한다. 저장 실패 상태에서 무작정 반복 수정하지 않는다. |

서버 실행 로그는 `%LOCALAPPDATA%\StudyPlanner\startup.log`와 `server-error.log`에서 확인한다. 저장 파일을 복구할 때는 현재 파일을 먼저 별도 백업한다. 복구 절차와 미전송 일정 보관 방식은 [Windows 배포 안내](windows-distribution.md)의 저장 장애 보호 항목을 참고한다.

## 8. 업데이트와 제거

- **설치판 업데이트:** 최신 ZIP을 풀어 `설치.cmd`를 실행한다. 프로그램만 갱신하고 개인 데이터는 유지한다. 업데이트 전 내보내기를 권장한다.
- **설치판 제거:** 설치 폴더 `%LOCALAPPDATA%\Programs\StudyPlanner`의 `제거.cmd`를 실행한다. 바로가기와 자동 시작을 해제하고 앱 소유 서버를 종료한다. 프로그램 폴더는 안내에 따라 직접 삭제하며, Lively 배경화면도 따로 해제한다. 개인 데이터와 백업은 남는다.
- **소스 방식의 자동 시작 해제:** 저장소에서 아래 명령을 실행한다. 현재 켜진 서버는 별도로 종료한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows-startup.ps1 -Remove
```

## 9. 처음 설치한 뒤 직접 확인할 것

- 가상의 일정을 추가하고 완료·해제·삭제한 뒤 새로고침해 상태가 유지되는지 확인한다.
- 배경화면에 같은 개인 일정, 학교 일정, 공휴일과 오늘 급식이 보이는지 확인한다.
- 달력 위치·크기와 잠금 설정이 다시 실행해도 복원되는지 확인한다.
- Windows 재로그인/재부팅 후 서버와 Lively가 다시 동작하는지 확인한다.

깨끗한 다른 PC 설치, 재부팅과 실제 Lively 적용, ARM 환경은 아직 별도 검증이 필요하다. 자동 테스트 통과가 이 환경들의 동작을 보장하지는 않는다.
