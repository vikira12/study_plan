# 프롬프트 설계서

## 1. 목표

개인이 학습할 일을 등록하고 마감까지 남은 일수를 확인하며, 완료 여부를 관리할 수 있는 웹앱을 만들어 줘. 마감이 가까운 일정을 눈에 띄게 표시하고 알림을 받아 계획한 기간 안에 일을 마칠 수 있게 해 줘.

## 2. 맥락

- 사용자는 일정의 제목과 마감 날짜를 입력해 할 일을 등록한다. 제목과 마감 날짜는 필수이며 마감 날짜는 오늘 또는 미래여야 한다.
- 등록한 일정은 목록에서 제목, 마감 날짜, 남은 일수 또는 마감 경과 여부, 완료 상태를 확인할 수 있다.
- 마감 임박 기준은 일정마다 1일 전, 3일 전, 7일 전 중에서 선택한다. 기본값은 1일 전이다.
- 임박 기준에 도달한 미완료 일정은 화면 상단 알림 영역과 일정 목록에서 강조한다. 브라우저 알림 권한이 허용되면 브라우저 알림도 한 번 보낸다.
- 브라우저 알림을 허용하지 않았거나 지원하지 않아도 화면 안의 경고는 볼 수 있어야 한다.
- 앱을 닫아 둔 사이 알림 기준 날짜가 지났다면, 다음에 앱을 열었을 때 아직 마감일이 지나지 않은 임박 일정을 확인하고 알린다.

## 3. 제약

- 작업 위치는 `D:\project\study_plan`이다.
- `index.html`, `style.css`, `app.js` 세 파일만 사용한다. 프레임워크, 빌드 도구, 외부 라이브러리, 서버는 사용하지 않는다.
- 일정은 해당 브라우저의 `localStorage`에 저장한다. 다른 기기나 브라우저와 동기화하지 않는다.
- 남은 일수는 사용자의 기기 현지 날짜를 기준으로 계산한다. 입력과 화면 표시에는 시간 단위를 사용하지 않는다.
- 앱이 열려 있는 동안 임박 여부와 남은 일수 표시를 주기적으로 갱신한다. 앱이 닫힌 동안 정해진 시각에 알림을 보내는 기능은 포함하지 않는다.
- 브라우저 알림은 사용자가 버튼을 눌렀을 때만 권한을 요청한다. 권한이 거부되어도 일정 관리는 계속 사용할 수 있어야 한다.
- 사용자가 입력한 제목을 화면에 표시할 때 HTML 코드로 실행되지 않도록 안전하게 처리한다.

## 4. 출력 형식

- 먼저 만들 파일 세 개와 각 파일의 역할을 한 줄씩 적어 줘.
- 화면에 보일 요소를 위에서 아래 순서로 적어 줘.
- 이후 세 파일의 코드를 작성하고 각 파일이 서로 연결되도록 해 줘.
- 마지막에 아래 완료 기준을 브라우저에서 각각 어떻게 확인했는지 적어 줘.

## 5. 완료 기준

1. 제목과 오늘 또는 미래의 마감 날짜를 입력하고 추가 버튼을 누르면 새 일정이 목록에 나타난다.
2. 일정의 완료 체크박스를 누르면 완료 상태가 화면에 표시되고, 다시 누르면 진행 중 상태로 돌아온다.
3. 일정의 삭제 버튼을 누르면 해당 일정이 목록에서 사라진다.
4. 제목을 비우거나 공백만 입력하고 추가 버튼을 누르면 오류 안내가 보이고 일정은 등록되지 않는다.
5. 일정을 추가하거나 완료 상태를 바꾼 뒤 새로고침해도 목록과 상태가 유지된다.
6. 마감 날짜가 선택한 임박 기준 안에 들어온 미완료 일정은 화면 상단과 목록에서 경고가 보인다. 브라우저 알림 권한을 허용했다면 알림도 한 번 표시된다.
7. 일정을 완료하거나 삭제하면 해당 일정의 임박 경고가 사라진다.
8. 마감 날짜가 지난 미완료 일정은 `기한 지남`으로 표시되고, 완료한 일정에는 임박 알림을 보내지 않는다.
9. 전체·진행 중·완료 필터를 선택하면 목록에 표시되는 일정이 해당 상태로 바뀐다.
10. 기존 일정의 제목·마감 날짜·알림 기준을 수정하고 저장하면 목록에 변경된 내용이 반영되며 새로고침 후에도 유지된다.

## 6. 추가하면 좋은 기능

- 일정 수정: 잘못 입력한 제목이나 변경된 마감 날짜를 다시 등록하지 않고 고칠 수 있다.
- 상태별 필터: 해야 할 일과 끝낸 일을 따로 볼 수 있다.
- 기한 경과 표시: 마감을 놓친 일을 바로 찾을 수 있다.
- 빈 목록 안내: 등록된 일정이 없거나 필터 결과가 없을 때 이유를 알 수 있다.
